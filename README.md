# ResumeIQ — Java Full-Stack AI Resume Analyzer

ResumeIQ is a Java 21 + Spring Boot + React/Vite application for secure resume uploads, resume text extraction, ATS-style job matching, AI feedback, and improved resume downloads. It intentionally uses a straightforward frontend structure and does not require Docker.

## Features

- Registration and login with BCrypt password hashing and JWT-protected APIs
- User-owned private resume and analysis records
- PDF and DOCX upload with server-side file validation and text extraction
- Deterministic ATS-style score and skill/keyword comparison
- General resume review or job-specific screening
- Editable improved-resume content with DOCX and PDF download
- Analysis history and basic dashboard
- Local heuristic mode for offline development; optional real Groq AI analysis and rewrite integration

> Scores are a transparent application heuristic, not a score from a particular employer's ATS. Always verify resume facts before submitting. In local `mock` mode, AI feedback is heuristic rather than generated by an LLM.

## Requirements

- Java 21
- Maven 3.9+
- Node.js 20+ and npm
- MySQL 8 for persistent MySQL usage (H2 in-memory database is the default for quick local startup)
- A Groq API key only if you enable the real Groq provider

## 1. Start the backend

From the project root:

```bash
cd backend
mvn clean test
mvn spring-boot:run
```

The backend runs at `http://localhost:8080`. Swagger UI is available at `http://localhost:8080/swagger-ui.html`. By default it uses an in-memory H2 database and local file storage under `backend/storage` when launched from the backend directory. H2 data is lost when the application stops.

### Use MySQL

Create a database and a dedicated database user, then set these environment variables before starting Spring Boot:

```bash
export SPRING_DATASOURCE_URL='jdbc:mysql://localhost:3306/resumeiq?useSSL=false&serverTimezone=UTC'
export SPRING_DATASOURCE_USERNAME='resumeiq_app'
export SPRING_DATASOURCE_PASSWORD='replace-with-your-local-password'
export SPRING_JPA_HIBERNATE_DDL_AUTO='validate'
export FLYWAY_ENABLED='true'
export JWT_SECRET='replace-with-a-random-secret-of-at-least-32-bytes'
```

The MySQL driver is selected from the JDBC URL. Flyway migrations are in `backend/src/main/resources/db/migration`. Set `APP_STORAGE_DIRECTORY` to a persistent private directory if you do not want files stored under `backend/storage`.

## 2. Start the frontend

In a second terminal from the project root:

```bash
cd frontend
npm ci
npm run dev
```

Open the URL printed by Vite (normally `http://localhost:5173`). Vite proxies `/api` to `http://localhost:8080` during local development.

For a production build:

```bash
npm run build
```

## 3. Enable real Groq AI analysis and resume rewriting

The project defaults to `AI_PROVIDER=groq`. If you do not have a Groq API key configured, set `AI_PROVIDER=mock` for local heuristic testing; this mode does not call an LLM. To use Groq for real LLM analysis and rewriting, set these variables before starting the backend:

```bash
export AI_PROVIDER='groq'
export GROQ_API_KEY='your-groq-api-key'
export GROQ_MODEL='llama-3.3-70b-versatile'
```

Restart the backend. The key is used only by Spring Boot; never put it in the frontend `.env` or commit it. AI calls send extracted resume text and, when supplied, the job description to the configured provider. Do not upload confidential documents unless you are comfortable with the provider's data-processing terms.

## Environment variables

See `.env.example` for the supported backend and frontend settings. Spring Boot environment variables take precedence over `application.yml`.

## Main API routes

- `POST /api/v1/auth/register` — register
- `POST /api/v1/auth/login` — login
- `GET /api/v1/auth/me` — current user
- `POST /api/v1/resumes` — upload PDF/DOCX (`multipart/form-data`, field `file`)
- `GET /api/v1/resumes` — list current user's resumes
- `POST /api/v1/analyses/general?resumeId={id}` — general review or job screening; JSON body `{ "jobDescription": "..." }`, may be empty for a general review
- `GET /api/v1/analyses` — analysis history
- `POST /api/v1/resumes/{id}/generate?analysisId={id}` — generate an improved version
- `PATCH /api/v1/generated-resumes/{id}` — save edited content
- `GET /api/v1/generated-resumes/{id}/download?format=docx` — download DOCX
- `GET /api/v1/generated-resumes/{id}/download?format=pdf` — download PDF

All resume, analysis, and generated-file endpoints require a bearer token and enforce resource ownership.

## Verification

Run `mvn clean test` in `backend` and `npm run build` in `frontend`. Test the complete workflow by registering a user, uploading a text-based PDF/DOCX resume, running an analysis, generating an improved version, editing it, and downloading DOCX/PDF. A scanned PDF without embedded text is rejected with a clear message; OCR is not included.

## Known limits

- Default local mode uses deterministic heuristics, not an LLM. Set `AI_PROVIDER=groq` and provide `GROQ_API_KEY` to enable real AI analysis and resume rewriting through Groq.
- Scanned-image PDF OCR is not included.
- JWT logout clears the browser's stored token; tokens already copied elsewhere remain valid until expiration because server-side token revocation is not implemented.
- Resume text extraction and AI recommendations can be imperfect; users must review generated content for accuracy.
